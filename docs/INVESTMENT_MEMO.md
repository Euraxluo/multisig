## 1. 定位与三层价值

**一句话定位**：把 Telegram/Discord 群聊直接升级为「有金库、有 Agent、有门限签名」的链上组织——组织身份不是多签地址，而是**成员设备端持有的 FROST 门限密钥分片**。

**技术形态（与普遍认知的差异点）**：
- DKG 生成 FROST 门限组织：**私钥从不存在于链上，也不存在单点**，分片在各成员设备端。这是"链上多签"之外的另一种托管范式。【链上可验证：委员会注册、epoch、签名验证逻辑；设备端分片保管属于设计属性，需审计报告佐证】
- 群成员可孵化 Agent（AgentCap），Agent 以**热土豆模式**取用群内资产——Cap 不可存储、必须在同一交易内被消费，天然防呆。【链上可验证：Move 类型的 ability 约束】
- **双闸门**：限额以下按 epoch 释放（自动、低摩擦）；限额以上需**加权提案 + FROST 门限签名**。【链上可验证：限额对象、提案权重、门限校验路径】

**三层价值**：

| 对象 | 痛点 | 本产品的解法 | 价值强度 |
|---|---|---|---|
| **群主** | 群收款/群资金靠人肉记账 + 单人钱包，跑路与误操作无法审计 | 组织金库 + 链上准入经济学 + 可被门限治理取回的创世质押，权责对等 | 强（可验证的信任替代） |
| **成员** | 参与 DAO 要装钱包、学治理、买 gas，转化率崩塌 | 群内身份即成员身份，bond 终态全额退（0.05–0.5 SUI 只是押金，不是成本） | 中强（摩擦显著低于 Realms 类） |
| **Agent 开发者** | 拿不到"有权限边界"的资金源，只能要求用户交出私钥或无限授权 | AgentCap 提供**可编程的支出上限 + epoch 重置 + 超额升级到人类门限签名** | 强（这是真正的差异化） |

[INFERENCE] 三层价值里，**只有第三层是结构性的**。群主/成员价值是"更好用的多签"，会被 Sui 原生多签和 Safe 类产品持续压价；Agent 权限粒度是当前竞品没有覆盖的空白。

## 2. 竞品对比

| 维度 | **本产品** | Safe{Wallet} | Squads (Solana) | Realms (SPL Governance) | Coinbase AgentKit / x402 |
|---|---|---|---|---|---|
| **托管模型** | 无链上私钥；分片在成员设备端（FROST） | 链上智能合约账户（EVM） | 链上程序账户（Solana） | 链上治理账户 + 金库 | 托管/非托管钱包 + HTTP 402 支付协议 |
| **签名方式** | t-of-n FROST 门限签名（单一聚合签名） | k-of-n 链上签名收集 | k-of-n 链上签名收集 | 代币投票 → 提案执行 | 单签（钱包或 MPC 服务商） |
| **成员变更成本** | [INFERENCE] 低——换人只需新一轮 DKG/reshare，地址与金库不变 | 链上治理交易，gas + 多签确认；地址不变 | 链上交易，rent + 手续费；地址不变 | 治理提案，周期以天计，注意力成本最高 | 不适用（无组织概念） |
| **Agent 权限粒度** | **高**：per-epoch 限额 + 热土豆 Cap + 超额升级门限签名（双闸门） | 无原生 Agent 层；需 Safe Modules/Guards 自研 | 无原生 Agent 层；需自研 | 无 | **低**：钱包级 session key / 单笔上限，无组织化治理升级路径 |
| **费用** | 创建费 0.005 SUI **销毁**；bond 0.05–0.5 SUI **终态全额退**；创世质押 90 天硬锁【链上可验证】 | [INFERENCE] 协议费 ≈ 0，仅 gas；Safe Token 不构成使用费 | [INFERENCE] 协议费 ≈ 0，rent + 手续费 | [INFERENCE] 协议费 ≈ 0，链上治理成本 | [INFERENCE] 协议费 ≈ 0，facilitator 承担 gas |

**结论性判断**：
1. **对 Safe/Squads/Realms，本产品不是费用竞争者**——大家都不收协议费，价格战没有意义。竞争点在**成员变更成本**与**Agent 层**。
2. **真正的替代品是 Sui 原生多签地址**：零部署成本、钱包原生支持。[INFERENCE] 但它每次成员变更要换地址，且完全没有 Agent 权限层——这是我们唯一站得住的护城河。
3. **AgentKit / x402 不是竞品，是上游需求源**：它们解决"Agent 怎么付钱"，我们解决"Agent 凭什么被允许花组织的钱"。x402 越普及，我们的双闸门越值钱——但也意味着 [INFERENCE] Coinbase 或 Sui 官方随时可能补上这一层。

> **§2 尾注（投委会前必做）**：核实 ① Safe 官方文档中的协议费/模块生态现状；② Squads 当前版本费率与 Agent 相关功能；③ Coinbase x402 的 adopters 与 facilitator 收费模式。本表上述三行标 [INFERENCE] 的单元格均待一手核实。

## 3. 商业模型：现状与三条收入路径

**现状（诚实版）**：

| 收钱点 | 金额 | 归属 | 是否构成收入 |
|---|---|---|---|
| 创建费 | 0.005 SUI | **销毁** | 否（通缩设计，非营收） |
| 参与 bond | 0.05–0.5 SUI | 终态**全额退**还成员 | 否（是押金/防女巫，不是收费） |
| 创世质押 | 90 天硬锁，可被 org 门限治理取回 | 锁在协议/金库 | 否（是承诺机制，不是收费） |

【链上可验证】以上三个数字与资金流向均可由合约直接核对。
**直白结论：当前产品没有任何收入面。** 这是一个有真实机制的协议，但还不是一门生意。以下三条路径按"改动量 / 时间 / 监管风险"排序。

**路径 A：企业白标（最快变现）**
- 对象：需要"团队金库 + AI 操作员"的 Web3 项目方、做市/运营团队、华语社群服务商。
- 收费：SaaS 年费（[INFERENCE] $2k–20k/年/组织）+ 部署服务费。
- 实现改动量：**小—中**。合约层几乎不动（最多加组织元数据/白名单对象）；主要是多租户前端、权限后台、账单系统。约 2–4 个 sprint，纯链下工作。
- 风险：销售驱动型收入，估值倍数低；但能最快证明"有人愿意付钱"。

**路径 B：Agent 交易抽成（最匹配产品形态）**
- 机制：在 Agent 取用资产的入口函数中扣取 bps（[INFERENCE] 10–30 bps），或按 epoch 收取"Agent 席位费"。
- 实现改动量：**中**。需要新增 fee config 对象、在 vault 取用路径插入扣费、处理与限额的交互（扣费是否占额度）、补测试与升级迁移。合约升级 + 全量回归，约 3–5 个 sprint。
- 风险：直接抬高 Agent 单笔成本，可能把小额高频场景（x402 式微支付）挤走——**抽成与"Agent 原生"定位存在张力**，建议只对超额通道收费、限额内免费。

**路径 C：创世质押金融化（想象空间最大、监管最脏）**
- 机制：把 90 天硬锁的质押仓位做成可转让/可组合凭证（类 LST），或引入第三方为质押者提供流动性。
- 实现改动量：**大**。需新增凭证对象、转让规则、与门限治理取回逻辑冲突的仲裁机制，且要重做安全模型（当前"硬锁"是承诺的可信来源，一旦可转让，承诺强度下降）。至少 2 个季度。
- 风险：**最高**。收益类凭证极易被认定为证券；且会破坏现有机制的经济意义（锁仓的价值就在于不可退出）。

> **投委会立场**：只批准 A，B 作为主网上线后的第一个合约升级储备，C 在取得法律意见前不做。

## 4. 市场规模（TAM / SAM / SOM）

全部为 [INFERENCE]，假设列在表内，任何一条假设被推翻，区间整体平移。

| 层级 | 估算 | 关键假设 | 置信度 |
|---|---|---|---|
| **TAM** | **$0.2–0.7B / 年** | ① DAO/团队金库管理软件 + 交易抽成：全球 DAO 管理资产 $20–40B，软件与抽成捕获 0.5–1%；② Agent 发起支付：2027 年链上 Agent 支付流水 $5–30B，捕获 0.3–1% | 低 |
| **SAM** | **$15–50M / 年** | Sui 生态 + 华语社群经济：Sui 生态金库/组织资产 $1–2B，占 TAM 的 5–8%；且能接受 FROST 设备端托管的用户群更窄 | 低 |

## 5. 风险矩阵

| 类别 | 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| **技术** | DKG/reshare 的 liveness 失败导致组织"锁死"（t 个分片凑不齐） | 中 | 高 | 需要可验证的**恢复/重置路径**（[UNVERIFIED] 是否已实现异步信箱与超时重协商）；主网前做故障注入测试（掉线 t-1 人、分片损坏） |
| **技术** | FROST 实现与 Move 校验层存在不一致（审计 0 Critical，但 2 High 是已修——修复本身的回归风险） | 中 | 高 | 要求出示 2 个 High 的修复 diff 与复测报告；上线前第二次审计（聚焦签名验证与限额边界）；421 个测试覆盖率高，但需确认**属性测试**与**模糊测试**占比 |
| **技术** | 合约可升级性 = 单点信任（升级密钥归谁？） | 中 | 高 | 必须明确升级多签/时间锁归属，最好用自身门限机制自举；否则"去中心化托管"叙事不成立 |
| **监管** | 华语社群 + 组织资金池 + Agent 自动支付，触碰支付/集资红线；创世质押金融化触及证券法 | 高 | 高 | 不做路径 C；前端做地理围栏；Token 层面不做任何收益承诺；[INFERENCE] 需一份管辖地法律意见（新加坡/香港二选一） |
| **监管** | 门限签名服务若被认定为"托管服务商"，需 KYC/牌照 | 中 | 中 | 强调**非托管**：分片在用户设备，团队无任何单点恢复能力——这既是合规优势，也是**产品风险**（用户丢分片即永久失去资产） |
| **采用** | **DKG 需 t 个真人同时在场**：见下方量化 | **高** | **高** | 优先支持**异步信箱**（成员 72h 内各自完成 DKG 轮次）；把"同时在线"从硬约束降级为软约束；产品上先跑 t=2/n=3 的极小组 |
| **采用** | bond + 90 天硬锁抬高早期用户心理门槛（即使可退，"锁 90 天"听起来像损失） | 中 | 中 | 前端把 bond 明确表述为"押金/可退"；创世质押改为可选档位，非强制 |
| **竞争** | **Sui 原生多签**免费、钱包原生、零学习成本 | 高 | 高 | 不在"多签"上竞争，只在 Agent 权限层与成员变更成本上竞争；把 AgentCap 做成开源标准的野心 |
| **竞争** | Coinbase / x402 生态向上补出"组织级 Agent 权限" | 中 | 高 | 抢先成为 Sui 事实标准；与 x402 做集成而非对抗 |
| **竞争** | Safe 若进入 Sui | 低 | 高 | 时间窗口约 12–18 个月，必须在此之前取得组织数 |

**采用风险专节（按要求重点）**：
设群规模 n=7、门限 t=5。若每次邀请的单人当次出席率 p=0.7：
- 单次同步 DKG 成功率 ≈ p^t = 0.7^5 ≈ **16.8%**。
- 允许 3 次重试：1−(1−0.168)³ ≈ **42%**。
- 若支持异步信箱（72h 窗口，出席率提升到 [INFERENCE] 0.85）：≈ 0.85^5 ≈ **44%**，且**不要求同时在线**，重试成本几乎为零，两周内累计完成率可到 [INFERENCE] 70%+。

结论：**同步 DKG 是转化率杀手，异步信箱不是"优化项"，是"生死项"。** 若当前版本只能同步完成 DKG，主网上线前必须补齐；否则每一个漏斗数字都会被 0.168 这个系数压垮。此外应默认推荐 t=2/n=3 的小组织起步，把 t/n 作为"随组织成长而升级"的能力，而不是初始配置。

2. **合约升级权限归属**——若为团队单点，叙事从"非托管"退回"团队托管"，折价显著。
3. **审计报告的可核验性**——[UNVERIFIED] 需看到报告原文、审计方名称、2 High 的修复复测。
4. **421 个测试的构成**——数量不是质量，需看集成测试与模糊测试比例。
5. **竞品动向**——Sui 官方若推出 Agent 权限原语，本项目价值归零。
6. **付费试点**——0 个付费意向 vs 1 个付费试点，是估值能否站在区间上沿的分水岭。

## 7. 结论

**条件式投资（Conditional YES）**：技术交付显著高于早期项目均值（正式审计 + 0 Critical + 421 测试 + 13 代 testnet 血统 + 双闸门设计），但**收入面为零、转化率未验证、护城河待考**。建议以**小额、里程碑分期**进入，金额锚定在 §6 区间下沿，并绑定以下三个必须验证的条件。

**必须验证的三个条件（全部通过才进入下一轮）**：

1. **DKG 转化率**：在真实群（非团队自测）中，**异步完成率 ≥60%、7 日内组织创建完成率 ≥40%**。若异步信箱尚未实现，本条件直接不成立，投资暂停。
2. **付费意向转合同**：至少 **1 份企业白标付费合同或 LOI**（路径 A），金额与交付范围明确。没有真实付费意向 = 没有商业模型。
3. **Agent 真实使用**：主网/准主网环境下，**≥30% 的组织在 30 天内产生 ≥1 次 Agent 发起的链上交易**，且 Agent 交易额占组织总流水 ≥20%。若 Agent 只是摆设，本产品就退化为"又一个多签"，条件不成立。

**只看的三个指标（其余一律不看）**：
1. **周活组织数（WAO）**——每周至少发生 1 次治理或 Agent 交易的独立组织数。这是唯一能证明"组织真的在用"的指标。
2. **Agent 交易额中位数（每组织每周）**——证明双闸门带来了真实资金流，而不只是演示。
3. **每组织年化收入（ARPO，含已签合同）**——证明有人付钱，而不是只有 TVL 和测试数。

**明确不做的事**：不因 testnet lineage 数字加价；不因 421 个测试数加价；不为 TAM 故事付溢价；不在取得法律意见前支持质押金融化。
