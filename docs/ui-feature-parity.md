## 最小结构与验收顺序

- 个人：概要与账户菜单 → 地址/收款与名片码 → 个人资产 → 个人活动 → 身份/关注/对象收件箱。通过可见群组入口进入对应 Group，不混入群余额。
- Group：群概要与真实金库 → 群聊 / 成员 / AI / 文件 / Tx / 收款各域；保留工具、模板、治理与跟投的明确归属。群分享查看码与收款码分别定义。
- DM：从个人身份/联系人进入一对一会话，保留单独的收件人、密钥、历史与签名状态；群文件、提案、资金不混入 DM。
- 支付 / 待办：六工具、完整模板与计划管理保持可见；待办明确列出交易与投票、历史和草稿。能力缺口必须能查看具体原因并保留配置，不能以隐藏或永久死按钮完成验收。

优先级：先验收旧数据不丢与组织关联，再验收真实成员审批/拒绝部署状态和金库执行，然后验证治理/跟投配置与历史，最后完成各尚缺服务并进行手机/桌面视觉验收。本文件不是部署、链上成功或全功能完成的声明。
